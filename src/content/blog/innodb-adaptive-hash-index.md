## 어댑티브 해시 인덱스 (Adaptive Hash Index)

> <strong>어댑티브 해시 인덱스(Adaptive Hash Index)</strong>는 사용자가 수동으로 생성하는 인덱스가 아닌, InnoDB 스토리지 엔진에서 **사용자가 자주 요청하는 데이터에 대해 자동으로 생성하는 인덱스**이다.<br>
> **데이터 페이지**를 **메모리(버퍼 풀) 내에서 접근하는 것을 더 빠르게 만드는 기능**이다. B-Tree 검색 시간을 줄여주기 위해 도입되었다.

InnoDB 스토리지 엔진은 자주 읽히는 데이터 페이지의 키 값을 이용해 해시 인덱스를 만든다. 필요할 때마다 어댑티브 해시 인덱스를 검색해서 레코드가 저장된 데이터 페이지를 즉시 찾아간다. B-Tree 에서 루트 노드부터 리프 노드까지 찾아가는 비용이 없어지고, 그만큼 CPU 는 적은 일을 하며 쿼리의 성능을 높인다. 이와 동시에 컴퓨터는 더 많은 쿼리를 동시에 처리할 수 있게 된다.

해시 인덱스는 **인덱스 키 값**과 **해당 인덱스 키 값이 저장된 데이터 페이지 주소** 쌍으로 관리되는데, **데이터 페이지 주소**는 실제 키 값이 저장된 데이터 페이지의 메모리 주소를 가진다. 이는 **InnoDB 버퍼 풀에 로딩된 페이지의 주소**를 의미한다.

그렇기 때문에 어댑티브 해시 인덱스는 버퍼 풀에 올려진 데이터 페이지에 대해서만 관리되고, 버퍼 풀에서 해당 데이터 페이지가 없어지면 어댑티브 해시 인덱스에서도 해당 페이지의 정보는 사라진다.

### 어댑티브 해시 인덱스의 효과

```sql
SELECT fd1 FROM tab WHERE idx_fd2 IN (?, ?, ?, ?, ...);
```

위와 같은 단순 쿼리를 어댑티브 해시 인덱스를 **비활성화 했을 때**와 **활성화 했을 때**를 비교하면 다음과 같은 결과를 확인할 수 있다.

어댑티브 해시 인덱스를 활성화한 후, 쿼리의 처리량은 2배 가까이 증가함과 동시에 CPU 사용률은 오히려 감소한 것을 확인할 수 있다.

어댑티브 해시 인덱스를 활용하면서 B-Tree 의 루트 노드부터 검색이 많이 줄어들게 되고, InnoDB 내부 잠금(세마포어)의 횟수가 상당히 줄어든다.

### ✅ 어댑티브 해시 인덱스가 도움이 되는 경우

- 디스크의 데이터가 InnoDB 버퍼 풀 크기와 비슷한 경우 (디스크 읽기가 많지 않은 경우)
- 동등 조건 검색 (동등 비교와 IN 연산자) 이 많은 경우
- 쿼리가 데이터 중에서 일부 데이터에만 집중되는 경우

### ❌ 어댑티브 해시 인덱스가 도움이 되지 않는 경우

- 디스크 읽기가 많은 경우
- 특정 패턴의 쿼리가 많은 경우(조인이나 LIKE 패턴 검색)
- 매우 큰 데이터를 가진 테이블의 레코드를 폭 넓게 읽는 경우

**어댑티브 해시 인덱스**는 **데이터 페이지를 메모리(버퍼 풀) 내에서 접근하는 것을 더 빠르게 만드는 기능**이다. 그렇기 때문에 디스크에서 페이지를 읽어오는 경우가 빈번하다면 전혀 도움이 되지 않는 것이다.

또한 어댑티브 해시 인덱스도 메모리 공간이라는 점을 간과해서는 안된다. 데이터 페이지의 인덱스 키가 해시 인덱스로 만들어져야 하고, 불필요한 경우 제거되어야 하며, 어댑티브 해시 인덱스가 활성화되면 InnoDB 스토리지 엔진은 그 키 값이 어댑티브 해시 인덱스에 있든 없든 항상 검색해봐야 한다는 것이다.

> 📌 **참고**
>
> MySQL 8.0 부터는 내부 잠금(세마포어) 경합을 줄이기 위해 <strong>어댑티브 해시 인덱스의 `파티션 기능`</strong>을 제공한다.
>
> 어댑티브 해시 인덱스의 파티션 기능은 어댑티브 해시 인덱스를 여러 개의 파티션으로 분할하여 각 파티션에 대한 잠금을 별도로 관리한다. 이렇게 함으로써, 여러 스레드가 동시에 어댑티브 해시 인덱스에 액세스할 때 서로 다른 파티션에 대한 액세스가 가능하므로, 내부 잠금 경합이 줄어들게 된다.
>
> 예를 들어, 어댑티브 해시 인덱스가 8개의 파티션으로 분할되어 있고, 8개의 스레드가 각각 다른 파티션에 대한 액세스를 수행하는 경우, 각 스레드는 서로 다른 잠금을 획득하므로 경합 없이 동시에 작업을 수행할 수 있다. 이렇게 함으로써, 전체적인 성능이 개선된다.
>
> **innodb_adaptive_hash_index_parts** 시스템 변수를 이용해 파티션 개수를 변경할 수 있고, 기본값은 8개이다.
>
> 만약 어댑티브 해시 인덱스가 성능에 많은 도움을 준다면 파티션 개수를 더 많이 설정해 세마포어 경합을 줄일 수 있다.
